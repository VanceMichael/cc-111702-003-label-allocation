# 电子面单作废与重开时的号码额度交接工作台
本项目用于为未领号包裹申请面单，登记号码和打印回执，显示当前可用号码及剩余额度；并支持按包裹办理破损面单重开，由本地承运平台与打印回执通道共同参与验证。
运行环境为 Node.js 22.23.4，仅使用标准库，没有运行时安装步骤。数据均为本地合成资料，默认来源只监听回环地址，不连接真实业务网站或真实账号。
## 运行
```bash
npm run build
npm test
npm run demo
```
演示会在进程内启动实际本地 HTTP 来源，先办理一次首次申领，再逐步推进一个包裹的重开全流程，打印领域结果及来源请求，然后关闭服务。端口由系统分配，数据保存在内存，不影响已启动的服务。
持续运行时先执行 `npm run source`，再在另一个终端执行 `npm start`。默认来源端口为 4101，业务端口为 4100；可通过 `SOURCE_URL`、`PORT` 和 `STATE_PATH` 指定回环来源、端口及状态文件。终止进程使用 Ctrl+C。删除 `var/` 可清空本地持久状态。
## 业务接口
`POST /collect` 接收本次办理参数，空对象使用本地样例的正常条件（保留原有首次申领用法）；`GET /state` 查询当前业务结果；`GET /health` 查询服务状态。一次办理失败不会提交中间业务状态，接口以 422 返回拒绝原因；来源断线等故障会登记并保持原办理阶段，不产生半成品。状态文件按完整写入后替换，单进程内串行办理。
- 首次申领：`{ "parcel": "P1", "requestId": "R1" }`（或空对象）。
- 重开续办：`{ "action": "reopen", "parcel": "P1" }`，每次只推进一个来源动作，可重复调用直到终态；断线后用相同参数续办，先恢复原进度再继续。
- 现场销毁确认：`{ "action": "confirm-destruction", "parcel": "P1" }`，只登记原纸销毁事实，不代表平台号码已回收。
- `numbers`：分配包裹与承运号码的关系，含历史失效号码，失效号码不会再次分配。
- `printing`：保存打印作业及现场回执。
- `quota`：核算平台确认的额度消耗；作废核实中的额度仍占用，平台确认回收后才释放。
每个包裹呈现当前号码、`printable`（能否打印）、`deliverable`（能否交寄）、`status/statusLabel`（重开阶段）、`waitingOn`（仍等待平台或现场确认的事项）与 `nextAction`。一个包裹重开期间不影响其他包裹办理。
来源接口的字段约定见 `docs/source-contract.md`，业务边界与重开状态机见 `docs/operations.md`。`fixtures/source.json` 是可独立启动的来源响应数据，来源 `GET /trace` 返回实际请求；脚本每条路由依次返回响应，超出后重复最后一条，可表达延迟、断连和明确拒绝。请求轨迹只记录是否带授权，不回显授权原文。
## 测试
测试覆盖领域正常结果、状态重开、HTTP 办理与查询、来源拒绝后的回滚、并行存储更新、本地访问边界、来源请求追踪，以及重开状态机全链路（双通道核实、现场销毁、作废受理与轮询、额度回收后重领、已交寄拒绝、断线恢复、终态不复活、多包裹隔离与持久化续办）。每个测试使用临时端口与独立状态，不依赖执行顺序。构建仅检查源码语法，不获取依赖。
