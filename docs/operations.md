# 业务运行边界
当前可查询：包裹当前号码、打印回执、剩余额度、重开阶段及等待事项、号码历史。
当前写入操作：首次领号、按包裹办理重开、现场销毁确认。
已有号码包裹不重复首次领号；一个包裹同时只允许一个可用承运号码，重开期间该包裹不可打印、不可交寄，其他包裹不受影响。

## 重开流程（按包裹，分步可恢复）
每个包裹的重开是一条独立状态机，每次办理只推进一个来源动作，进度随状态持久化，断线或进程退出后再次进入同一包裹时先认清原阶段再继续，不会为返回成功另领新号。
1. `verify-print`：向打印回执通道核实原作业是否真的打印过（回执可能晚于人工申请到达）。
2. `verify-platform`：向承运平台核实号码状态与是否已交寄。已交寄号码进入终态 `refused-handover`，不作废、不另领号。
3. `await-destruction`：仅当存在打印事实时，等待现场确认原纸已销毁。该确认只解决纸面问题，不代表平台号码已回收。
4. `void-request`：向平台发起作废。平台受理（pending）不等于作废完成。
5. `void-pending`：轮询作废结论。平台同意作废也不抹掉曾经打印、交寄的事实；只有 `completed` 且 `quotaReturned=true` 才进入下一步。
6. `reissue-ready`：旧号标记失效（不再显示为可交寄），额度确认回收后才可重新领号。
7. `done`：新号生效；或终态 `void-rejected` / `reissue-failed`。重开最终失败时旧面单保持失效，不会复活显示。

## 额度规则
取消中的额度仍然占用，不得先借给其他申请；只有平台确认回收（`quotaReturned`）后该额度才重新可用。工作台按"未回收号码条目"核算占用，而不是按包裹数核算。

## 原始依据
来源请求保存方法、路径、状态、字节数与响应摘要，不保存授权原文。拒绝或不完整响应不能作为领域收件成功；业务结果和请求收据分别可查。进程内的写入序列只保证本进程存储互斥，不代表来源具备幂等或多进程协调能力。
来源网络故障（断线、超时）登记为来源故障并保持原阶段，不提交半成品状态；来源明确的业务拒绝（4xx 带业务原因）按领域规则转为对应终态。

## 领域决定
号码职责确定包裹申领身份及号码独占，历史失效号码也不得再次分配；打印职责接纳打印事实并决定是否可再打；额度职责在接纳前核对扣减与来源余额，作废核实中的额度不得挪用；重开职责编排打印回执通道与承运平台的共同验证，并对每个包裹独立呈现可打印、可交寄与等待事项。
这些拒绝属于当前正常办理契约，不代表来源失败可视为业务成功。各决定在状态提交前完成，拒绝不会消耗本地办理状态。
